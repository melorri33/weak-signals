# Weak Signals — сервис поиска слабых сигналов (кейс Газпромбанк.Тех)

Этот файл читают все агенты Claude в проекте. Здесь общие правила; задачи конкретной роли — в `.claude/agents/<роль>.md`. История решений, принятых до создания репозитория, — в `docs/HANDOFF.md`.

## Что строим

Сервис принимает свободный запрос («перспективные решения в финтехе»), ищет по открытым источникам и выдаёт **топ-15 зарождающихся технологий (слабых сигналов)**. У каждого сигнала есть уверенность модели, объяснение и источники. Зрелые технологии, хайп и шум отсеиваются с указанием причины.

Два этапа:

1. **Модель на датасете.** Классификатор «слабый сигнал / нет» с точностью не ниже 75–80% и объяснимостью (SHAP).
2. **Открытый поиск.** Конвейер: запрос → сбор источников → кандидаты → признаки → отсев и скоринг → карточки топ-15 → веб-интерфейс.

Сроки: промежуточная сдача ≈ 28.09.2026 (конвейер в консоли/API + отчёт по метрикам + методология). Дата финала уточняется.

**Слабый сигнал** — технология на ранней стадии: публикаций пока мало, но их число быстро растёт; в основном статьи, препринты и патенты, мало новостей и рекламы; нет стандартов, явных лидеров и сформированного рынка.

## Жёсткие требования ТЗ — нарушать нельзя

1. **Никаких трендов «из головы» LLM.** Каждый сигнал в выдаче опирается минимум на один реальный документ, собранный из открытых источников. Ссылки берутся только из собранных документов, LLM их не генерирует.
2. **Модели.** Локальные — любые с Hugging Face (основной вариант у нас — Qwen через Ollama). Облачные — только из списка ТЗ: YandexGPT Lite 5, YandexGPT Pro 5/5.1, Qwen3.6 35B-A3B, Qwen3 235B, GigaChat 2 Lite/Pro/Max, gpt-4.1, gpt-5.6-luna. Другие модели, автовыбор модели и посредники (OpenRouter и т.п.) — только после согласования с организаторами.
3. **Логирование моделей.** Каждый вызов LLM, эмбеддингов и классификатора записывается через `log_model_call`: какая модель, на каком шаге.
4. **Всё для пользователя — на русском.** Для зарубежных источников — русское резюме, при этом сохраняются оригинальное название, ссылка, дата и язык. Автоперевод или генеративное резюме помечается рядом с источником.
5. **По каждому источнику показываем** название, ссылку, дату публикации, тип, язык оригинала и уровень доверия.
6. **Соцсети, блоги, агрегаторы, пресс-релизы** — только как подсказка. Они не могут быть единственным основанием для сигнала, иначе ставится пометка о пониженном доверии.
7. **В выдаче ровно топ-15** ранних технологий. Зрелые, массовые, стандарты, хайп и шум исключаются, причина исключения сохраняется и показывается.
8. **Запуск:** Docker, README с командами, работа на обычном ноутбуке.
9. **Стек из ТЗ:** Python, PostgreSQL, FastAPI (или Django), React или Streamlit.

## Поток данных

```
запрос
 → llm.expand_query            10–20 поисковых фраз RU+EN
 → collectors.collect          до 500 документов из всех источников
 → storage.save_documents
 → pipeline.extract_candidates 40–60 технологий-кандидатов
 → collectors.term_stats       статистика по каждому кандидату (статьи/патенты/новости по годам)
 → features.compute            признаки
 → filters.apply               отсев зрелого, хайпа, шума (с причиной)
 → model.score                 уверенность + топ-причины (SHAP)
 → llm.make_card               карточки топ-15 только по найденным документам
 → SearchResult → api → ui
```

## Контракты между модулями

Все типы данных — в `src/common/schemas.py` (pydantic v2). Пример полного результата — `tests/fixtures/search_result_example.json`.

| Модуль | Функция | Вход → выход | Владелец |
| --- | --- | --- | --- |
| collectors | `async collect(phrases, limit=500)` | `list[str]` → `list[Document]` | Данные |
| collectors | `async term_stats(term)` | `str` → `TermStats` | Данные |
| storage | `save_documents`, `get_documents`, `save_search_result`, `get_search_result` | `Document` / `SearchResult` | Данные |
| llm | `expand_query(query)` | `str` → `list[str]` | Интеграция |
| pipeline | `extract_candidates(docs)` | `list[Document]` → `list[Candidate]` | Интеграция |
| features | `compute(candidate, docs, stats)` | → `CandidateFeatures` | ML |
| trust | `level_for(url, source_type)` | → `TrustLevel` | Продукт |
| filters | `apply(candidate, features)` | → `FilterDecision` | Продукт |
| model | `score(candidates, features)` | → `list[ScoredCandidate]` | ML |
| llm | `make_card(scored, docs)` | → `SignalCard` | Интеграция |
| pipeline | `async run(query)` | `str` → `SearchResult` | Интеграция |
| api | `POST /search`, `GET /search/{run_id}`, `GET /signal/{run_id}/{candidate_id}` | JSON по схемам | Интеграция |

**Сначала заглушка.** В первый день каждый владелец кладёт заглушку своей функции: правильная сигнатура, валидные фейковые данные по схеме. Так никто никого не ждёт. Заглушку потом заменяем реализацией, не меняя сигнатуру.

## Стек и соглашения

- Python 3.11, pydantic v2, httpx (async), FastAPI, Streamlit, PostgreSQL 16 + pgvector, SQLAlchemy 2 / psycopg 3, CatBoost, SHAP, sentence-transformers, Ollama.
- Конфиг — только через `.env` → `src/common/config.py`. Секреты и ключи не коммитим; новые переменные добавляем в `.env.example`.
- Новая зависимость → в `requirements.txt` и упомянуть в PR.
- Имена в коде — на английском. Комментарии, docstrings, тексты интерфейса, сообщения коммитов — на русском.
- Типы везде, функции небольшие, без глобального состояния.
- `ruff format` и `ruff check` перед коммитом.
- Тесты: pytest. Основные тесты работают офлайн на фикстурах; тесты с сетью помечаем `@pytest.mark.network`.
- Логи: `from src.common.logs import get_logger, model_timer`. Вызов модели оборачиваем в `with model_timer(step, model, provider):` — он сам пишет в журнал прогона.
- На каждый сетевой вызов — таймаут. Падение одного источника или шага не валит весь конвейер: пишем в лог и идём дальше.

## Git

- `main` — только через PR, мёржит artiom.
- Ветки: `ml/…`, `data/…`, `integ/…`, `product/…`.
- PR маленькие (до ~300 строк). В описании: что сделано, как проверить, какие контракты затронуты.
- Перед PR: `ruff check .` и `pytest -m "not network"`.
- Раз в день конвейер на `main` должен проходить целиком: `python -m src.pipeline.cli "перспективные решения в финтехе"`.

## Как работать агенту Claude в этом репо

- Перед задачей прочитай свой файл роли в `.claude/agents/` и `src/common/schemas.py`.
- Работай маленькими шагами: функция → тест → запуск на реальных данных → показать результат человеку.
- Не выдумывай, как устроены внешние API: проверяй документацией и реальным запросом.
- Не выдумывай факты, ссылки и метрики. Если что-то не получилось — так и скажи.
- Объясняй человеку сделанное простыми словами: ему защищать это перед жюри.
- Не хватает контракта или нужна правка в чужой папке — остановись и опиши, что нужно, для владельца.
