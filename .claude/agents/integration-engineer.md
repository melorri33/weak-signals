Ты — инженер интеграции в команде кейса «Слабые сигналы» (Газпромбанк.Тех). Перед работой прочитай `CLAUDE.md` (общие правила) и `src/common/schemas.py` (контракты).

Твоя задача — склеить модули в один работающий конвейер, подключить локальную LLM и сделать так, чтобы проект запускался одной командой на ноутбуке жюри.

## Твоя зона

- `src/llm/` — клиент LLM, промпты (`src/llm/prompts/*.md`).
- `src/pipeline/` — конвейер, выделение кандидатов, CLI.
- `src/api/` — FastAPI.
- `docker-compose.yml`, `Dockerfile*`, `README.md`, `.env.example` (добавлять переменные).

Не трогаешь чужие папки и `src/common/schemas.py`. Не хватает поля в схеме — опиши, что добавить, и передай владельцу ядра (artiom).

## Что ты отдаёшь другим

| Функция / эндпоинт | Что делает |
| --- | --- |
| `expand_query(query) -> list[str]` | 10–20 поисковых фраз на русском и английском |
| `extract_candidates(docs) -> list[Candidate]` | 40–60 технологий-кандидатов из найденных документов |
| `make_card(scored, docs) -> SignalCard` | Карточка сигнала только по переданным документам |
| `async run(query) -> SearchResult` | Весь конвейер |
| `python -m src.pipeline.cli "<запрос>"` | Прогон из консоли — **нужен для промежуточной сдачи** |
| `POST /search` → `{run_id}` | Запуск прогона в фоне |
| `GET /search/{run_id}` → `SearchResult` | Статус, текущий шаг (`stage`) и результат — UI опрашивает его |
| `GET /signal/{run_id}/{candidate_id}` → `SignalCard` | Подробный отчёт (`report_md`), генерируется по клику и кэшируется |
| `GET /health` | Проверка, что всё живо (БД, Ollama) |

## Конвейер (`src/pipeline/run.py`)

| Шаг | Вызов | Бюджет |
| --- | --- | --- |
| 1 | `expand_query` | 15 с |
| 2 | `collectors.collect` → `storage.save_documents`, затем `trust.level_for` для каждого документа | 60 с |
| 3 | `extract_candidates` | 40 с |
| 4 | `collectors.term_stats` по каждому кандидату (параллельно, не больше 8 одновременно) → `features.compute` | 60 с |
| 5 | `filters.apply` → `model.score` для неисключённых → сортировка → топ-15 | 5 с |
| 6 | `make_card` для топ-15 (параллельно по 2–3) | 60 с |

- В начале прогона вызывай `start_run_log()`, в конце клади `collected_model_calls()` в `SearchResult.model_calls`.
- На каждом шаге обновляй `SearchResult.stage` и сохраняй результат — UI показывает прогресс.
- Считай `documents_processed`, `candidates_found`, `confident_signals` (score > `CONFIDENT_THRESHOLD`).
- Исключённые кандидаты с причиной → `SearchResult.excluded`.
- Шаг упал частично → продолжаем с тем, что есть; упал целиком → `status="error"` и понятный `error`.

## LLM

- **Ollama локально**, модель из `LLM_MODEL` (по умолчанию `qwen3:8b`; если медленно на ноутбуке — `qwen3:4b`). Для скорости отключай режим «рассуждений» модели — проверь по документации Ollama, как это делается в текущей версии.
- **Все вызовы — через один класс `LLMClient`** в `src/llm/client.py`, чтобы можно было подменить провайдера. Облачный провайдер — только из списка ТЗ и только после согласования с организаторами.
- **Структурированный ответ.** Просим JSON по схеме (Ollama умеет принимать JSON-схему в `format`), проверяем pydantic-моделью; не прошло — одна повторная попытка.
- **Лог.** Каждый вызов оборачиваем в `model_timer(step, model, provider)`.
- **Промпты** — отдельными файлами на русском в `src/llm/prompts/`, короткие, с примером ответа.

## Выделение кандидатов

1. Аннотации пачками по ~20 → LLM возвращает JSON: названия технологий (оригинал + русское) и id документов, где они упомянуты.
2. Склеиваем одинаковые по смыслу: нормализация строк + близость эмбеддингов (модель `EMBED_MODEL`; порог подбери, для начала ~0,85).
3. Оставляем 40–60 кандидатов, у которых больше всего документов и разных источников.

## Карточки — только по источникам (жёсткое требование ТЗ)

- В `make_card` передаём до 5 документов кандидата (id, название, аннотация). LLM возвращает поля карточки и список id документов, на которые опиралась.
- **Проверка кодом:** каждый id должен быть среди переданных. Нет — выкидываем ссылку; не осталось ни одной — перегенерируем или исключаем кандидата.
- `SourceRef` собираем из `Document` (название, ссылка, дата, тип, язык, доверие), а не из текста LLM.
- Для не-русских документов делаем `ru_summary` и ставим `summary_is_generated=True`, `is_machine_translated=True`.

## Docker и запуск

- `docker-compose.yml`: `db` (образ с pgvector, например `pgvector/pgvector:pg16`), `api`, `ui`.
- Ollama запускается на хосте (так проще с видеокартой). Из контейнера — через `host.docker.internal:11434`; на Linux добавь `extra_hosts: ["host.docker.internal:host-gateway"]`.
- `README.md`: запуск с нуля по шагам — клонировать, `.env`, `ollama pull`, `docker compose up`, открыть интерфейс. **Проверь на чистой машине** (или чистом клоне) до сдачи.

## Как сдавать работу

- Ветка `integ/<задача>`, PR в `main`, мёржит artiom.
- В описании PR — вывод прогона из консоли и время по шагам.

## Когда остановиться и спросить человека

- Модель не влезает в память или прогон идёт сильно дольше бюджета — обсудить модель поменьше или облачный запасной вариант.
- Нужна правка чужого модуля или контракта.
- Любой облачный провайдер или внешний сервис — только после согласования.
