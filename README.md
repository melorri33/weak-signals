# Weak Signals

Сервис ищет **зарождающиеся технологии (слабые сигналы)** по свободному запросу: собирает статьи,
препринты, патенты и новости из открытых источников, отсеивает зрелое, хайп и шум и возвращает
топ-15 ранних технологий с уверенностью модели, объяснением и ссылками на источники.

Кейс Газпромбанк.Тех. Контекст проекта и правила работы команды — в [CLAUDE.md](CLAUDE.md).

## Что уже работает

Конвейер целиком проходит в консоли. Часть шагов пока заглушки (они честно помечены в логе
прогона строками «… ещё не готов — работаю на заглушке»):

| Шаг | Состояние |
| --- | --- |
| Расширение запроса в поисковые фразы | локальная LLM, при недоступности — фразы из самого запроса |
| Сбор источников и статистика по терминам | настоящие источники: техноновости, OpenAlex, arXiv, Hacker News, Википедия |
| Хранилище | PostgreSQL; база не поднята — конвейер работает, но прогон не переживёт перезапуск |
| Выделение кандидатов | заглушка на правилах (LLM + эмбеддинги — дальше по плану) |
| Признаки и скоринг | CatBoost со SHAP-объяснением |
| Уровни доверия и правила отсева | настоящие: `config/trust_domains.yaml`, `config/filter_rules.yaml` |
| Карточки сигналов | источники настоящие (только из собранных документов), тексты — заглушка |
| API и интерфейс | FastAPI (`POST /search`, `GET /search/{run_id}`) и Streamlit |

## Запуск с нуля

Нужны: macOS или Linux, Python 3.11, Docker, ~10 ГБ на диске под модель.

### 1. Код и зависимости

```bash
git clone <адрес репозитория> && cd weak-signals
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # править не обязательно, значения по умолчанию рабочие
```

### 2. Локальная LLM (Ollama на хосте)

```bash
# macOS: brew install ollama && brew services start ollama
# Linux: curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3:8b            # ~5 ГБ — рабочая модель
ollama pull qwen3:4b            # ~2,5 ГБ — по желанию: вдвое быстрее, но качество ниже
ollama list                     # модель должна быть в списке
```

Если в системе настроен HTTP-прокси, добавь `localhost` в `NO_PROXY` — иначе запросы к Ollama
пойдут через прокси. Наш код к Ollama ходит мимо прокси сам, а вот `curl` придётся подсказать:
`curl --noproxy '*' http://localhost:11434/api/tags`.

### 3. База данных

```bash
docker compose up -d db
docker compose ps               # состояние healthy
```

База пока нужна только для хранения документов и прогонов (модуль `src/storage`); конвейер
работает и без неё.

### 4. Прогон

```bash
python -m src.pipeline.cli "перспективные решения в финтехе"
```

Полезные флаги:

```bash
python -m src.pipeline.cli "квантовые вычисления в банках" --json out.json   # сохранить весь SearchResult
python -m src.pipeline.cli "финтех" --json > result_fintech.json             # JSON в stdout, без отчёта
python -m src.pipeline.cli "финтех" --no-progress                           # без строк прогресса
```

JSON прогона нужен для проверки «как у жюри» (`python -m src.model.eval_search result.json`): она считает,
сколько технологий датасета нашлось на шагах «документы → кандидаты → топ-15». Файл датасета есть только
у владельца ядра, поэтому JSON прогонов по шести областям отправляем ему.

Выдача в консоли: поисковые фразы → топ сигналов (уверенность, описание, преимущество, кейс,
почему ранний сигнал, ключевые предикторы, источники со ссылками, датой, типом, языком и уровнем
доверия) → исключённые кандидаты с причиной → список вызовов моделей.

### 5. API

```bash
uvicorn src.api.main:app --reload
```

Полный прогон идёт минуты, поэтому `POST /search` не ждёт результата: он заводит прогон и сразу
отдаёт `run_id`, а выдачу забирают по `run_id`.

| Запрос | Что делает |
| --- | --- |
| `GET /health` | доступны ли модель и база; в `notes` — по-русски, что не поднято |
| `POST /search` `{"query": "..."}` | запускает прогон, отвечает `202` и `SearchResult` со `status='running'` |
| `GET /search/{run_id}` | текущее состояние: `stage` — шаг конвейера, `status='done'` — выдача готова |
| `GET /signal/{run_id}/{candidate_id}` | карточка одного сигнала из выдачи |

```bash
curl -s localhost:8000/health
run=$(curl -s -X POST localhost:8000/search -H 'content-type: application/json' \
      -d '{"query":"перспективные решения в финтехе"}' | python -c 'import json,sys; print(json.load(sys.stdin)["run_id"])')
curl -s localhost:8000/search/$run | python -m json.tool | head -20
```

Прогон на ноутбуке идёт один за раз: локальная модель одна, и два прогона одновременно уводят
машину в swap. Пока прогон не закончился, второй `POST /search` отвечает `429` с номером текущего.
Документация эндпоинтов со схемами — на `/docs`.

## Настройки

Все параметры — через `.env` (образец в [.env.example](.env.example)):

| Переменная | Зачем | По умолчанию |
| --- | --- | --- |
| `LLM_PROVIDER` | провайдер LLM; поддерживается `ollama` | `ollama` |
| `LLM_MODEL` | модель в Ollama; в `.env.example` стоит `qwen3:4b` | `qwen3:8b` |
| `OLLAMA_URL` | адрес Ollama | `http://localhost:11434` |
| `EMBED_MODEL` | модель эмбеддингов для склейки кандидатов | `BAAI/bge-m3` |
| `DATABASE_URL` | подключение к PostgreSQL | `postgresql+psycopg://weak:weak@localhost:5432/weak_signals` |
| `MAX_DOCUMENTS` | сколько документов собираем максимум | `500` |
| `SOURCE_TIMEOUT_S`, `COLLECT_BUDGET_S` | таймаут источника и бюджет всего сбора | `15`, `60` |

## Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| `Ollama недоступна на http://localhost:11434` | не запущен Ollama: `brew services start ollama` или `ollama serve` |
| `Модель … не скачана` | `ollama pull qwen3:8b` (или та, что стоит в `LLM_MODEL`) |
| В логе «… ещё не готов — работаю на заглушке» | так и задумано: модуль ещё пишется, конвейер идёт дальше |
| Прогон падает на `db` | база не нужна для CLI; если нужна — `docker compose up -d db` |
| Прогон идёт дольше 5 минут | выгрузи лишние модели (`ollama stop qwen3:4b`) или поставь `LLM_MODEL=qwen3:4b` |
| API отвечает `429` | прогон уже идёт, номер текущего — в тексте ошибки; дождись его или посмотри `GET /health` |
| В `GET /health` `database_available: false` | `docker compose up -d db`; без базы прогоны живут только в памяти сервера |

### Сколько времени занимают шаги

Замеры на MacBook Air M1 (16 ГБ). Расширение запроса прогонялось по шести областям датасета:

| Модель | Скорость генерации | Один вызов `expand_query` | Качество фраз |
| --- | --- | --- | --- |
| `qwen3:8b` | ~4,8 токенов/с | 60–92 с | 18 годных фраз во всех шести областях |
| `qwen3:4b` | ~8,8 токенов/с | 25–31 с | в двух областях из шести мусор: шаблоны и выдуманные термины |

Поэтому рабочая модель — **`qwen3:8b`**: расширение запроса делается один раз за прогон, а от его
качества зависит, найдётся ли технология вообще. На слабой машине можно поставить
`LLM_MODEL=qwen3:4b` — прогон станет быстрее, но часть запросов даст плохие фразы.

Полный прогон через API по запросу «перспективные решения в финтехе» занял **172 с**: расширение запроса 60 с
на `qwen3:8b`, сбор 387 документов, 60 кандидатов (пока правилами), скоринг 0,1 с, карточки на заглушке.
Как только кандидаты и карточки пойдут через модель, время вырастет — за ним следим отдельно.

Время каждого шага пишется в лог прогона (строки «Шаг … из … с бюджета») — по ним видно, где
конвейер упирается в бюджет. Держать в памяти сразу две модели на 16 ГБ нельзя: машина уходит
в свап, и обе замедляются. Выгрузить лишнюю: `ollama stop qwen3:4b`.
