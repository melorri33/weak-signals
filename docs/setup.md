# Развернуть проект на новой машине

> Написано при переезде с ноутбука (без видеокарты) на ПК с RTX 3060. Здесь всё, чего нет в репозитории:
> папка `data/` и `.env` в него намеренно не попадают.

## 1. Что поставить

```bash
winget install --id Python.Python.3.11 -e
winget install --id Ollama.Ollama -e
winget install --id Git.Git -e
winget install --id GitHub.cli -e
```

Дальше — репозиторий и окружение:

```bash
git clone https://github.com/melorri33/weak-signals.git
cd weak-signals
py -3.11 -m venv .venv
.venv/Scripts/pip install -r requirements.txt
```

## 2. Модель

Берём 14B: в 12 ГБ видеопамяти она помещается (около 9 ГБ в квантовании Q4) и заметно аккуратнее
мелких моделей в том, что для нас важнее всего — выписать из новости технологию, а не название продукта.

```bash
ollama pull qwen3:14b
```

**Обязательно проверить, что модель целиком на видеокарте.** Запусти любой запрос и посмотри:

```bash
ollama ps
```

В колонке `PROCESSOR` должно быть `100% GPU`. Если там появится доля CPU, значит модель не поместилась
(обычно из-за длины контекста) — скорость упадёт в десятки раз. Тогда либо `qwen3:8b`, либо более
жёсткое квантование 14B.

На процессоре (старый ноутбук) приходилось держать 4B: 8B давала 2.2 токена в секунду, шаги не
укладывались в бюджеты, а 4B путала технологии с названиями продуктов.

## 3. Что перенести руками

Ничего из этого нет в git — копировать с ноутбука.

| Что | Откуда | Зачем |
| --- | --- | --- |
| `.env` | корень проекта | ключ OpenAlex и настройки; **в чат и в репозиторий не выкладывать** |
| `data/*.xlsx` | датасет организаторов | обучение и проверка качества |
| `data/positive_terms.csv`, `data/labeled_set.csv` | обучающая выборка | обучение модели и проверка «как у жюри» |
| `data/openalex_years_phrase.json`, `data/attention_stats.json`, `data/openalex_types_orgs.json` | кэши статистики | признаки обучающей выборки, без них не воспроизвести метрики |
| `data/cache/`, `data/llm_cache/` | кэши источников и ответов модели | не обязательно, но экономит время и бюджет OpenAlex |
| `data/search_runs/` | сохранённые прогоны | нужны для демонстрации без ожидания |

## 4. Проверить, что всё поднялось

```bash
.venv/Scripts/python -m pytest -m "not network"
```

Дальше — быстрый прогон и интерфейс:

```bash
.venv/Scripts/python -m src.pipeline.cli "перспективные технологии в энергетике"
.venv/Scripts/streamlit run src/ui/app.py
```

Первый прогон на 14B стоит сравнить с сохранённым прогоном на 4B (`data/search_runs/Edge.json`,
область Edge): там видно, как выглядели кандидаты и русские названия на слабой модели.

## 5. Что поменять после переезда

На видеокарте шаги идут в разы быстрее, поэтому бюджеты, задранные под процессор, надо вернуть
к разумным. Это не украшательство: большой бюджет маскирует настоящие проблемы со скоростью.

| Где | Значение на процессоре | К чему стремимся на видеокарте |
| --- | --- | --- |
| `LLM_MODEL` в `.env` | `qwen3:4b` | `qwen3:14b` |
| `CANDIDATES_BUDGET_S` (`src/pipeline/run.py`) | 900 | 180 |
| `BUDGET_S` (`src/pipeline/candidates.py`) | 720 | 150 |
| `CARDS_BUDGET_S` (`src/pipeline/run.py`) | 600 | 150 |
| `MAX_DOCS_FOR_LLM` (`src/pipeline/candidates.py`) | 80 | все собранные документы |

Порядок такой: сначала прогон на новых значениях, потом правка цифр по факту — в таблицу
раздела 5 `docs/architecture.md` нужно занести измеренное время, а не желаемое.

## 6. База (необязательно)

Конвейер работает и без неё, просто прогоны не переживают перезапуск:

```bash
docker compose up -d db
```
