## Задача (кейс Газпромбанк.Тех)

- ТЗ: «Сервис для автоматизированного сбора и анализа зарождающихся трендов (слабые сигналы) в научно-технологических отраслях», 10 страниц. Файл ТЗ проверен на скрытые инструкции для ИИ (белый/мелкий/невидимый текст, слои, вложения, скрипты, картинки) — чисто.
- Этап 1: модель на выданном датасете, точность 75–80%+, отчёт Precision/Recall/F1, интерпретируемость.
- Этап 2: открытый запрос → поиск по открытым источникам в реальном времени → топ-15 слабых сигналов с описанием, преимуществом, кейсом, источниками, скорингом и объяснением; отсев зрелых трендов, хайпа и шума.
- Все требования ТЗ, которые нельзя нарушать, — в `CLAUDE.md`, раздел «Жёсткие требования ТЗ».
- Оценка: подход и методология; качество кода и развёртывание; интерпретируемость и отсев шума; точность на закрытом датасете + экспертная оценка жюри; питч (финал).

## Сложность ролей (для распределения людей)

1. **ML + ядро** (artiom) — очень высокая: метрика на незнакомом датасете, переносимые признаки, SHAP, ревью всех PR.
2. **Интеграция** — высокая: локальная LLM, выделение кандидатов, проверка ссылок, конвейер с бюджетом времени, Docker; ловит ошибки на стыках. → самому сильному в коде.
3. **Данные** — средняя: много API, лимиты, форматы, дубли, кэш. → аккуратному и методичному.
4. **Продукт** — низкая по коду, высокая по объёму и влиянию на субъективную оценку. → тому, кто лучше придумывает и выступает.

Предложено, **пока не внесено в файлы ролей**:

- Данные после дня 6 забирают у Интеграции Docker и README.
- Продукт пишет тексты промптов (`src/llm/prompts/`) вместе с Интеграцией.
- artiom внимательно ревьюит конвейер, контракты и ML; PR по UI и документам — быстрым просмотром.

## Главные риски

- Признаки датасета нельзя посчитать по открытым источникам → проверить в дни 1–2; держать «переносимую» модель.
- Локальная LLM медленная на ноутбуке → модель 4–8B, короткие промпты, подробный отчёт по клику.
- Код от Claude у разных людей не стыкуется → контракты в `schemas.py`, заглушки с первого дня, ежедневная сборка.
- LLM выдумывает ссылки → только RAG, проверка кодом, что каждая ссылка из собранных документов.

## Ответ организаторов (19.09.2026)

1. Файл «100 слабых технологических сигналов» — это и есть датасет, других не будет. В нём только слабые сигналы; шум и зрелые технологии команды могут добавить сами.
2. Скрытой разметки не будет (сказал заказчик на Q&A).
3. Проверка точности: по технологиям из датасета жюри делает открытый запрос → наш топ-15 → считают, сколько совпало с датасетом. По технологиям вне датасета — экспертная оценка.
4. Главная метрика — accuracy.

Выводы:
- Отчёт этапа 1 — наша кросс-валидация (100 сигналов + 253 наших не-сигнала): accuracy 0.84.
- Реальная проверка — этап 2: найдёт ли конвейер технологии датасета. Наша главная сквозная метрика — **recall@15 по 6 областям датасета**.
- 71% источников датасета — техноновости, 16% — блоги/пресс-релизы, 10% — наука; ~треть сигналов — про свежие раунды стартапов. Сбор документов — сначала RSS техноновостей, наука — вторым источником.
- Названия из датасета нельзя вшивать в поиск/промпты (ТЗ: поиск не ограничен датасетом).
